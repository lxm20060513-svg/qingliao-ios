// Agent 结果卡片协议（```ql-card 围栏）—— 给后端 / Agent / Prompt 作者的最短说明
//
// 目的：Agent 跑完后，让结构化结果以「卡片」呈现，而不是把一串键值/清单摊成纯文字。
// 客户端解析器：qingliao/Core/AgentCardParser.swift，渲染：qingliao/Features/Chat/AgentResultCard.swift
//
// ─────────────────────────────────────────────
// 1. 格式：```ql-card 围栏 + 单个 JSON 对象
// ─────────────────────────────────────────────
//
// 已经修好路由器，结果如下：
//
// ```ql-card
// {"type":"result","title":"家庭网络体检","subtitle":"2026-09-10 21:40",
//  "status":{"text":"已完成","tone":"ok"},
//  "metrics":[{"label":"下载","value":94.2,"unit":"Mbps","tone":"ok"},
//             {"label":"延迟","value":18,"unit":"ms"}],
//  "fields":[{"key":"路由器","value":"小米 RM1800"}],
//  "list":[{"title":"重启路由器","subtitle":"耗时 2 分钟","status":"完成","tone":"ok"},
//          {"title":"刷新 DNS 缓存","status":"跳过","tone":"warn"}],
//  "table":{"columns":["设备","IP"],"rows":[["NAS","192.168.31.40"]]},
//  "footer":"共 2 项操作"}
// ```
//
// 其余文字照常写在围栏外（Markdown 正常渲染，代码块/图片/表格不受影响）。
//
// ─────────────────────────────────────────────
// 2. 字段（全部可选，有什么写什么；没有内容的段客户端不画）
// ─────────────────────────────────────────────
// type      result | metrics | list | table | status  —— 只影响头部图标/强调色
// title     卡片标题（一句话）
// subtitle  次要说明（时间戳/来源）
// status    "已完成" 或 {"text":"已完成","tone":"ok"}
// fields    [{"key","value","tone"?}]          键值行
// metrics   [{"label","value","unit"?,"tone"?}] 大号指标（客户端数值滚动）
// list      [{"title","subtitle"?,"status"?,"tone"?}] 清单项（字段名也接受 items/text/detail）
// table     {"columns":[...],"rows":[[...]]}   表格（横向可滚）
// footer    页脚小字
//
// tone 取值：ok / warn / error / info（也接受 success、warning、fail、中文「完成/异常/提示」等别名），
// 未知或省略 → 蓝色（info）。
// value 允许字符串或数字（数字 12.0 会显示为 12；布尔显示「是/否」；数组用「、」连接）。
//
// ─────────────────────────────────────────────
// 3. 三条红线（客户端已保证，后端照写即可）
// ─────────────────────────────────────────────
// ① 零回归：没有 ```ql-card 标记、或 JSON 不合法、或卡片为空 → 原文完全按普通 Markdown/纯文本渲染，
//    一个字都不丢（解析失败时围栏内容连 ``` 一起原样显示）。
// ② 流式安全：围栏没闭合前一律按文本显示（客户端先暂存），闭合的瞬间才替换成卡片 —— 不会出现半截卡片。
//    因此可以放心地流式输出，不需要等全部结束再吐卡片。
// ③ 只认小写 `ql-card`（兼容 `ql_card` / `qlcard`）；围栏必须独占一行，整块必须是**一个** JSON 对象，
//    不要在一个围栏里塞多个对象或多个卡片（要多张卡就写多个围栏）。
//
// 4. 建议的落点
// ─────────────────────────────────────────────
// Agent 结果类回复（体检/诊断/巡检/清单/表格式回答）在文字总结后面补一张卡：
// 结论放 title+status，关键数字放 metrics，逐项结果放 list，明细放 table。
// 闲聊/解释类回复不必用卡片。
